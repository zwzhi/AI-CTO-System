# 阶段门禁检查清单

## 使用规则

本文按标准路径展开：

**IDEA → RESEARCH → EVALUATION → DESIGN → DEVELOPMENT**

每次转换都必须留下证据、下一动作和可追溯记录。清单中的“输入”是门禁评审所需材料，“输出”是门禁结束后必须形成的结果，“验收标准”决定能否转换，“未通过处理”规定项目停留或退回的位置。

根据 [ADR-0001](../adr/ADR-0001-PROJECT-LIFECYCLE-ORDER.md)，当价值与范围的不确定性高于可行性不确定性时，可以采用：

**IDEA → EVALUATION → RESEARCH → DESIGN**

采用替代路径时：

1. IDEA → EVALUATION 仍要满足 Idea 完整性要求，并记录先评估价值与范围的原因。
2. EVALUATION 的假设、证据缺口和风险问题成为后续 Research 的输入。
3. Research 完成后必须用新证据刷新或确认 Evaluation、项目评分、Confidence 和风险分析。
4. 进入 DESIGN 前仍执行本文的 EVALUATION → DESIGN 统一门禁；Research 与 Evaluation 必须全部完成，顺序调整不构成跳过许可。

## IDEA → RESEARCH

### 输入

- [ ] 项目候选 README 和 PROJECT_STATE 已创建。
- [ ] 问题、目标用户、预期价值、初始需求、范围边界与约束已记录。
- [ ] 已知历史项目、相关决策和可复用资产已关联。
- [ ] 关键假设、未知项和首要调研问题已列出。
- [ ] 用户已确认继续探索该 Idea。

### 输出

- [ ] Research 范围、问题清单、方法、信息源类型和完成条件。
- [ ] 需要验证或证伪的假设及其优先级。
- [ ] 调研责任人、时间边界和预期交付物。
- [ ] PROJECT_STATE 中的 Current Stage、Confidence、Evidence、Next Action 更新记录。
- [ ] 进入 RESEARCH 的用户确认与证据引用。

### 验收标准

- [ ] Idea 能明确回答“为谁解决什么问题、希望产生什么结果”。
- [ ] 范围足以形成可执行的 Research 问题，且没有把解决方案预设为结论。
- [ ] 关键约束和已知风险已显式记录。
- [ ] 每个优先调研问题都有可验证的完成条件。
- [ ] 用户明确同意进入 RESEARCH。

### 未通过处理

- 保持 IDEA，不启动正式调研。
- 补充用户、问题、范围、约束或历史关联；无法收敛的 Idea 记录暂缓原因与重启条件。
- 若用户未确认，记录待确认事项和下一次确认触发点，不以沉默代替批准。
- 若发现与现有项目重复，先完成合并、复用或停止的判断。

## RESEARCH → EVALUATION

### 输入

- [ ] 已确认的 Research 范围、问题、假设和完成条件。
- [ ] 可核验的来源清单，包含来源位置、发布日期或访问日期。
- [ ] 调研发现、反证、冲突信息、限制与尚未解决的问题。
- [ ] 技术、市场、成本、合规、安全、数据、许可证和运营等相关风险证据。
- [ ] 当前 PROJECT_STATE 与 PROJECT_MEMORY。

### 输出

- [ ] Research 文档，包含范围、方法、来源、发现、结论、限制、风险与建议。
- [ ] 关键结论到来源的追溯关系。
- [ ] 已验证、被否定和仍未确定的假设清单。
- [ ] 可供 Evaluation 使用的价值、范围、可行性、资源和风险证据包。
- [ ] PROJECT_STATE 与 PROJECT_MEMORY 的调研摘要和下一动作更新。

### 验收标准

- [ ] Research 的约定范围和完成条件均已满足。
- [ ] 关键结论可追溯到可信来源，事实、推断和建议相互区分。
- [ ] 相互冲突的证据已呈现并说明处理方式，没有只保留支持性证据。
- [ ] 限制、证据缺口和过期风险已记录，并评估其对结论的影响。
- [ ] 信息足以评估项目价值、范围、资源、可行性和风险。
- [ ] Research 结果的 Confidence 已记录。

### 未通过处理

- 保持 RESEARCH，按证据缺口补充来源、实验、访谈或方案比较。
- 调研问题过宽时缩小范围并重新确认完成条件；关键假设失效时返回 IDEA 重定问题或范围。
- 对无法消除的冲突证据降低 Confidence，并在进入 Evaluation 前说明影响。
- 不得为了开始评分而隐藏未知项或把推断写成事实。

## EVALUATION → DESIGN

### 输入

- [ ] Research 已完成，且路径、版本、日期和关键证据可追溯。
- [ ] Evaluation 已完成，包含成功标准、价值、范围、资源、可行性、优先级和立项建议。
- [ ] 100 分制各维度得分、依据、计算规则和总分。
- [ ] 总体及关键结论的 Confidence、理由和证据引用。
- [ ] 风险分析，包含责任人、缓解措施、剩余风险和红线状态。
- [ ] Build vs Buy 分析，或“不适用”的理由与批准记录。
- [ ] 当前项目范围和全部评审文档的版本基线。

### 输出

- [ ] 按 [项目立项门禁](./PROJECT_APPROVAL_GATE.md) 形成的完整检查结果。
- [ ] 与总分唯一对应的行动建议：优先开发、进入 MVP 验证、继续研究或暂缓。
- [ ] 用户对当前范围和文档版本的明确决定记录。
- [ ] APPROVED_FOR_DESIGN、NEEDS_EVIDENCE、NOT_APPROVED 或 DEFERRED 的最终结果。
- [ ] PROJECT_STATE 与 PROJECT_MEMORY 的决定、证据和下一动作更新。

### 验收标准

- [ ] Research 与 Evaluation 均完成；采用替代顺序时，Evaluation 已用后续 Research 证据刷新或确认。
- [ ] 分项与总分可复算，分数建议使用无重叠、无空档的区间。
- [ ] 进入 DESIGN 所依赖的总体或关键结论至少为 L2，并达到当前决策风险所需等级。
- [ ] 不存在已触发且未关闭的红线，剩余风险已有明确接受者。
- [ ] 证据、分数、Confidence、风险、替代方案与建议已完整展示给用户。
- [ ] 用户明确批准当前范围与文档版本进入 DESIGN。
- [ ] 所有批准条件均已关闭，最终结果为 APPROVED_FOR_DESIGN。

### 未通过处理

- 任一硬门槛未满足时保持当前阶段，不得进入 DESIGN。
- 缺少证据、关键结论为 L1 或未达到决策风险所需等级时，返回 RESEARCH 补证；评估逻辑或范围失效时留在或返回 EVALUATION 修订。
- 90–100 分仍会因红线、L1 关键结论、证据等级不足、文档缺失或无用户批准而阻断。
- 70–89 分按 MVP 验证建议收窄范围、设定周期、成功条件和停止条件，再重新评审。
- 50–69 分继续研究；0–49 分暂缓，并记录重启条件。
- 用户不批准或要求补充条件时，记录决定和下一动作；条件关闭后重新执行完整门禁。

## DESIGN → DEVELOPMENT

### 输入

- [ ] 已批准进入 DESIGN 的立项门禁记录及其范围基线。
- [ ] 已确认的 PRD，包含目标、范围、非范围、需求、非功能要求和验收标准。
- [ ] 已确认的 Architecture，引用 PRD 版本并说明组件边界、接口、数据、安全和技术约束。
- [ ] 已确认的 Development Plan，引用 Architecture 版本并列出任务、顺序、依赖、责任、验证方法和完成条件。
- [ ] 验收测试方案或用例，覆盖功能、非功能要求、环境、测试数据、预期结果和通过条件。
- [ ] 开发与交付风险清单，包含责任人、缓解措施、监控信号和剩余风险。
- [ ] 回滚方案，包含触发条件、操作步骤、数据备份与恢复、回滚后验证和责任人。
- [ ] 影响架构、数据、接口、安全、成本、流程或长期维护的已接受 ADR。
- [ ] 当前 PROJECT_STATE 与 PROJECT_MEMORY。

### 输出

- [ ] PRD、Architecture、Development Plan、验收测试、风险与回滚方案的确认版本基线。
- [ ] 需求 → 架构组件 → 开发任务 → 验收测试的可追溯关系。
- [ ] 已关闭的评审问题与已接受的剩余风险记录。
- [ ] 用户对当前范围、计划、验收方式、风险和回滚方案的明确确认。
- [ ] PROJECT_STATE 转换为 DEVELOPMENT 的证据与 Next Action。
- [ ] PROJECT_MEMORY 中的设计决定、限制和开发启动摘要。

### 验收标准

- [ ] PRD 的目标、范围、需求和验收标准明确且已获确认。
- [ ] Architecture 引用当前 PRD；每个组件可追溯到需求或非功能约束，重大决策有 Accepted ADR。
- [ ] Development Plan 引用当前 Architecture；任务范围、顺序、依赖、验证和完成条件可执行。
- [ ] 每项必须满足的需求至少对应一项验收测试，预期结果和判定标准明确。
- [ ] 风险有责任人和处置方案，不存在未解决的开发阻断项。
- [ ] 回滚触发条件、步骤、数据保护、恢复验证和责任人完整且可执行。
- [ ] 文档之间没有未解决的范围、接口、数据或计划冲突。
- [ ] 用户明确确认上述文档版本并授权进入 DEVELOPMENT。
- [ ] PROJECT_STATE 和 PROJECT_MEMORY 的状态转换记录位置已确定。

### 未通过处理

- 保持 DESIGN，禁止开始编码、配置生产环境或执行不可逆实施。
- PRD、Architecture、Development Plan、验收测试、风险与回滚方案中的缺口返回对应文档责任人修订并重新评审。
- 若发现价值、范围或关键可行性假设失效，退回 EVALUATION 或 RESEARCH，并记录原因和受影响文档。
- 用户未确认、确认对应旧版本或提出未关闭条件时，不得进入 DEVELOPMENT。
- 所有阻断项关闭、文档重新基线化并取得用户确认后，重新执行完整门禁。
