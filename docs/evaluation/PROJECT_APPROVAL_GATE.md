# 项目立项门禁

## 目的

本门禁用于判断项目是否可以从评估阶段进入 DESIGN。它把项目评分与立项批准分开：评分只给出行动建议，不能替代证据审查、风险判断或用户决定。

进入 DESIGN 前，Research、Evaluation、风险分析和项目评分必须全部完成，并且结论可追溯到证据。项目还必须通过红线与 Confidence 检查，并取得用户对当前范围和文档版本的明确批准。

Research 与 Evaluation 的顺序遵循 [ADR-0001](../adr/ADR-0001-PROJECT-LIFECYCLE-ORDER.md)：二者可以按首要不确定性调整先后，但不得跳过任一项。评分与批准分离遵循 [ADR-0002](../adr/ADR-0002-PROJECT-EVALUATION-AND-APPROVAL.md)。

## 基本原则

1. **证据先于结论**：每个关键结论都要引用来源、日期和对应文档位置；无法追溯的判断按未完成处理。
2. **评分只是建议**：总分用于确定推荐动作，不直接产生 DESIGN 或 DEVELOPMENT 资格。
3. **硬门槛不能被总分抵消**：未完成 Research 或 Evaluation、关键结论为 L1、存在未解决红线、缺少风险处置或缺少用户批准时，项目不得进入 DESIGN。
4. **用户批准必须明确**：沉默、未回复、仅认可某个观点或此前对旧版本的批准，都不等于批准当前项目进入 DESIGN。
5. **条件必须先关闭**：带未完成条件的决定记为待补证或未批准；条件关闭并复核前，不得更新状态为 DESIGN。
6. **进入 DESIGN 不等于开始开发**：即使门禁通过，也必须完成 DESIGN → DEVELOPMENT 门禁后才能编码或实施。

## 必需输入与证据

| 门禁项 | 必需证据 | 通过标准 | 阻断情形 |
|---|---|---|---|
| Research 完成 | Research 文档路径、版本或提交、日期；调研问题、来源、发现、反证、限制、风险与建议 | 调研范围已完成，关键结论能追溯到来源，未决问题已显式记录 | 文档缺失；关键来源不可核验；范围未完成；关键未知项未处理 |
| Evaluation 完成 | Evaluation 文档路径、版本或提交、日期；价值、范围、成功标准、资源、可行性、优先级与建议 | 评估维度完整，判断依据明确，并吸收当前 Research 证据 | 维度缺失；仍引用过期或冲突证据；成功标准或可行性结论不清 |
| 项目评分完成 | 100 分制各维度得分、依据、权重或计算规则、总分与复核人 | 分项可复算，总分位于 0 至 100，且与 Evaluation 使用同一证据版本 | 只有总分没有依据；计算不可复核；用高分覆盖证据缺口 |
| Confidence 完成 | 总体 Confidence、关键结论 Confidence、理由及其证据引用 | 进入 DESIGN 所依赖的关键结论至少为 L2；高影响、难回滚或生产承诺所依赖的结论已按风险提升到 L3；不确定性与补证动作已记录 | 总体或任一关键立项结论为 L1，或未达到该决策风险要求的等级，且尚未补证或降低范围消除依赖 |
| 风险分析完成 | 风险类别、触发条件、可能性、影响、责任人、缓解措施、剩余风险、红线状态和复核日期 | 风险可追踪；所有红线均为未触发或已用证据证明关闭；剩余风险有明确接受者 | 红线已触发且未关闭；无责任人或处置方案；关键剩余风险无人接受 |
| Build vs Buy | 分析文档，或“不适用”的理由与批准记录 | 涉及采购、复用、外部服务或自建选择时已完成比较；不适用时理由充分 | 存在实现路径选择但未比较成本、时效、控制力、锁定和退出风险 |
| 用户批准 | 批准人、日期、确认渠道或记录位置、批准范围、所审文档版本、限制条件 | 用户明确同意当前范围进入 DESIGN，且所有前置条件已关闭 | 无明确批准；批准对应旧范围或旧证据；批准仍附有未关闭条件 |

## 评分建议与边界

设总分为 S，取值范围为 0 至 100。区间使用“左闭右开”，最高区间包含 100，因此无重叠、无空档：

| 判定条件 | 整数分示例 | 行动建议 |
|---|---|---|
| 90 ≤ S ≤ 100 | 90–100（90+） | 优先开发；仍须先通过本门禁进入 DESIGN，再通过 DESIGN → DEVELOPMENT 门禁 |
| 70 ≤ S < 90 | 70–89 | 进入 MVP 验证；限定验证范围、周期、成功条件和停止条件，涉及实现时仍须经过 DESIGN |
| 50 ≤ S < 70 | 50–69 | 继续研究；围绕关键证据缺口、风险或价值假设补证后重新评估 |
| 0 ≤ S < 50 | 0–49（<50） | 暂缓；记录原因、重启条件和复核触发器 |

边界解释：90 分属于 90+，不属于 70–89；70 分属于 70–89，不属于 50–69；50 分属于 50–69，不属于 <50。若评分含小数，仍按上表的不等式判断。

这些区间只决定推荐动作。90 分以上不会自动获准立项；70–89 分也只有在硬门槛全部通过且用户明确批准后，才能进入以 MVP 验证为目标的 DESIGN。任何分数都不能抵消红线、L1 关键结论或缺失证据。若最终决定偏离分数建议，决策记录必须说明理由、影响与批准人，但不得借此绕过硬门槛。

## 门禁执行步骤

1. **冻结评审基线**：记录项目范围以及 Research、Evaluation、评分、Confidence 和风险分析的路径、版本与日期。
2. **核对完整性**：逐项检查必需输入，任何缺失都先返回责任阶段补齐。
3. **检查硬阻断**：确认关键结论不为 L1，并达到当前决策风险所需等级；红线未触发或已经关闭，剩余风险已被有权限的人接受。
4. **生成评分建议**：按唯一分数区间确定推荐动作，不改写原始分数以适配期望结论。
5. **请求用户决定**：向用户展示证据摘要、分数建议、Confidence、风险、替代方案和门禁结论。
6. **记录并执行决定**：只有 APPROVED_FOR_DESIGN 可以触发状态转换；其他结果保持当前阶段并记录下一动作。
7. **同步可追溯状态**：在 PROJECT_STATE 中更新 Current Stage、Confidence、Evidence、Next Action，并在 PROJECT_MEMORY 留下决策摘要。

## 门禁检查清单

- [ ] 已记录本次评审的项目范围和文档基线。
- [ ] Research 已完成，来源、结论、限制和风险可追溯。
- [ ] Evaluation 已完成，并使用当前 Research 证据。
- [ ] 各维度评分、计算规则和总分可复核。
- [ ] 总分已按唯一边界映射到行动建议。
- [ ] 总体及关键结论 Confidence 已记录，进入 DESIGN 所依赖的结论至少为 L2，并达到当前决策风险所需等级。
- [ ] 风险分析已完成，责任人、缓解措施和剩余风险明确。
- [ ] 不存在已触发且未关闭的红线。
- [ ] Build vs Buy 已完成，或不适用理由已获确认。
- [ ] 用户看到当前证据、评分建议、Confidence、风险和替代方案。
- [ ] 用户明确批准当前范围和文档版本进入 DESIGN。
- [ ] 决策、证据引用、下一动作和状态更新位置已记录。

**判定规则**：以上项目必须全部勾选，结果才能是 APPROVED_FOR_DESIGN。任一项未满足时，结果只能是 NEEDS_EVIDENCE、NOT_APPROVED 或 DEFERRED。不存在可直接进入 DESIGN 的“有条件通过”。
