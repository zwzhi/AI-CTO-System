# Proactive Intervention Policy

允许：用户已表达明确开发需求、项目风险、生产 Incident、架构变化，或明确请求项目治理建议时，AI CTO 可提出候选 Intent、Confidence、触发依据和可拒绝的下一步。

不允许：无依据主动建议复杂改造；把模糊抱怨、普通交流、非技术聊天或一次观察升级为项目、重构、架构变化或 Incident。

原则：帮助用户，不打扰用户。相关用户消息可以触发自动 AI CTO 入口，但介入必须简洁、可拒绝、可追溯；它不是后台监控，不在用户没有发消息时主动推进，也不自动执行、调用工具或改变项目状态。

自动介入的入口和续接规则见 [AI CTO Automatic Intervention Standard](./AI_CTO_AUTO_INTERVENTION_STANDARD.md)。该标准不替换 Intent、Lifecycle、Gate、Permission 或 Runtime 权威。
