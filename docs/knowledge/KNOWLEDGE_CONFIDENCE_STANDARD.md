# Knowledge 可信度标准

## 1. Evidence 强制要求

所有 Knowledge 必须保存可访问、可追溯的 Evidence。没有 Evidence 的内容只能作为 L1 假设，不得因 AI 表述完整、作者职位或重复引用提高可信度。

Evidence 至少记录：Source、日期、版本、项目 / 数据范围、观察或实验方法、原始结果、反证、限制、Owner、完整性位置和访问 / License 边界。

## 2. L1–L4 等级

| Level | 定义 | 允许用途 |
|---|---|---|
| `L1` | AI 推测、个人假设或未验证总结 | 生成问题、Research 或实验，不得作为强制决策依据 |
| `L2` | 公开资料、官方文档、论文、外部案例或供应商资料支持 | 方案参考和调研输入；关键结论需当前项目验证 |
| `L3` | 在一个真实项目、真实 Bug、正式实验或生产结果中验证 | 可在相同 / 高度相似范围内支持决策，仍需适用性检查 |
| `L4` | 在多个独立项目、环境或长期周期中重复验证 | 可作为高优先级复用候选，但不自动成为当前项目规则 |

公开资料数量增加不自动从 L2 升到 L3。多个复制同一来源的项目也不构成独立 L4 Evidence。

## 3. Evidence Level 与 Confidence

Registry 分开记录：

- **Evidence Level：** 支持该知识的最高验证类型，使用 L1–L4。
- **Confidence：** 对当前知识结论整体可信度的保守等级，同样使用 L1–L4，并综合证据覆盖、冲突、时效、范围、方法和反例。

Confidence 不得高于关键结论所依赖的有效 Evidence Level。高等级旧 Evidence 若与当前范围不匹配，当前复用判断必须降低 Confidence，而不是改写原记录的历史等级。

## 4. 决策强度

- L1：只能提出待验证假设。
- L2：可以支持 Research、候选比较和可逆实验；不能成为高风险或强制标准的唯一依据。
- L3：可以在匹配范围内支持正式设计或修复建议，仍须经过项目 Gate。
- L4：可以成为默认检索和优先复用候选，但当前项目证据、风险和 Gate 仍有否决权。

安全、法律、财务、隐私、生产发布和难回滚决策需要与影响匹配的独立 Evidence，不能仅凭历史 L4 模式自动批准。

## 5. 降级与复核

来源撤回、版本变化、证据过期、复现失败、适用范围缩小或出现高质量冲突时，保留原 Evidence Level 历史，同时降低当前 Confidence、把状态转为 `VALIDATING` 或 `DEPRECATED`，并记录触发器。

每项 Knowledge 必须设置 Last Validated 与 Next Review。时效要求随技术、供应商、法规、价格、模型和业务变化速度提高。
