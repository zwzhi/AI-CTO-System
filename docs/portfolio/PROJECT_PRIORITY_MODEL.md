# 项目优先级评分模型

## 1. 目的

本模型用 100 分制比较多个项目的相对资源优先级。它只生成 Portfolio 资源分配建议，不自动决定项目启动、继续、发布或停止。

项目评分必须绑定 Portfolio Snapshot、项目版本、Evidence、评估日期和 Confidence。不同证据覆盖率或时间窗的分数不得直接比较而不披露差异。

## 2. 评分维度

| 维度 | 分值 | 高分含义 |
|---|---:|---|
| 商业价值 | 25 | 用户结果、收入、节省、业务连续性或数据资产价值明确且可验证 |
| 战略价值 | 20 | 与长期路线、核心能力、差异化和关键约束高度一致 |
| 紧急程度 | 15 | 存在明确时间窗口、延迟成本或必须处理的外部变化 |
| 复用价值 | 15 | 能形成跨项目技术、数据、流程或知识资产 |
| 资源成本 | 10 | 所需人力、时间、算力与机会成本低或投入效率高 |
| 风险 | 15 | 风险已知、可控、可逆且有验证与回滚能力 |
| **合计** | **100** | 分数与 Confidence、红线、投资授权分别判断 |

资源成本和风险使用正向评分：成本越低、投入效率越高，资源成本得分越高；风险越低、控制越成熟，风险得分越高。不得把“成本高”或“风险高”直接换算成高优先级分。

## 3. 通用评分方法

每个维度先评 0–5，再按 `维度得分 = 维度上限 × 原始评分 ÷ 5` 折算：

| 原始分 | 判断标准 |
|---:|---|
| 5 | 有当前、直接、可复核证据，影响显著且持续 |
| 4 | 主要证据充分，存在有限且不改变结论的缺口 |
| 3 | 价值或条件成立，但范围、证据或执行仍有明显不确定性 |
| 2 | 仅部分成立，依赖关键假设或较高机会成本 |
| 1 | 证据弱、影响有限或与组合目标关系很小 |
| 0 | 不成立、方向相反、不可接受或无法建立可信依据 |

每项必须记录原始分、折算分、证据、Confidence、判断理由和补证动作。总体 Confidence 取影响资源建议的关键结论最低等级，不对 Confidence 求平均。

## 4. 维度判断依据与示例

| 维度 | 主要依据 | 高分示例 | 低分示例 |
|---|---|---|---|
| 商业价值 | 用户规模、需求强度、收入、节省、风险避免、数据价值 | 已验证关键用户结果并有可测收益 | 只有概念兴趣，没有目标用户或结果证据 |
| 战略价值 | 路线图、核心能力、差异化、合规与生态 | 建立未来多个项目必需的平台能力 | 与核心路线无关的一次性演示 |
| 紧急程度 | 法定期限、市场窗口、Incident、EOL、延迟成本 | 明确期限且延迟会造成不可恢复损失 | 没有时间窗口，延期影响很低 |
| 复用价值 | 可复用模块、数据、架构、Prompt、流程和知识 | 资产可服务多个已确认项目 | 高度定制且无法迁移到其他场景 |
| 资源成本 | 人力、周期、AI、基础设施、供应商和机会成本 | 小投入即可验证并形成高价值结果 | 长周期、高锁定、挤占关键维护资源 |
| 风险 | 技术、用户、数据、安全、合规、依赖和可逆性 | 风险边界清晰，可灰度、回滚并验证 | 关键依赖未知、不可逆且存在红线 |

## 5. 优先级等级

| Priority Score | 等级 | 默认资源建议 |
|---:|---|---|
| 80–100 | 高优先级 | 优先进入投资评审和容量规划 |
| 60–79 | 中优先级 | 分阶段验证、补证或在容量允许时安排 |
| 0–59 | 低优先级 | 暂缓投入、缩小范围或保留观察 |

最终分数保留一位小数，按原始数值判断等级，不通过四舍五入跨级。

## 6. Evidence Coverage 与缺失数据

没有有效证据的维度标记 `UNASSESSED`，不得主观赋分。此时只输出已评估小计、未评估分值、可能区间、Evidence Coverage、Provisional 标记和补证动作。所有维度有当前证据后才能发布 Final Priority Score。

## 7. 约束与复核

优先级分数不能抵消安全、数据、合规、License、不可恢复风险、关键依赖阻断或未关闭 P0 / P1。高分项目仍可能得到 `PAUSE` 或 `RESEARCH` 建议，低分项目也可能因 Incident 或法定义务获得保护性资源。

战略、预算、资源容量、依赖、成本、健康、用户证据或项目范围变化时重新评分，保留旧版本和差异。禁止为支持既定偏好而调整权重、时间窗或证据口径。
