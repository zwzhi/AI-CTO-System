# Model Routing Policy

## 目的与边界

Model Routing 只定义模型**类别**的建议原则，不指定供应商、模型名称、价格、API 或自动切换机制。实际模型使用受用户授权、可用 Capability、数据政策、成本预算、质量要求和安全约束控制。

| 模型类别 | 候选任务 | 选择条件 | 不适用情形 |
|---|---|---|---|
| 快速模型 | Level 0–1、低风险格式化、摘要、局部文档处理 | 质量要求明确且可快速验证，成本 / 时延优先 | 高风险、复杂推理、敏感数据或无法验证质量。 |
| 标准模型 | 常规分析、文档、研究归纳和项目任务 | 需要稳定结构化输出与适度推理 | 明确需要深度规划或代码专用能力。 |
| 高推理模型 | Level 3–4、重大风险、架构权衡、复杂冲突 | 证据不足、跨层影响或高质量要求需深度分析 | 可由更低类别可靠完成的低风险任务。 |
| 代码模型 | 有批准设计、任务、测试和工程约束的实现 / 评审 | 需理解或生成代码，并有验证路径 | 未完成 Design / Gate 或仅为一般咨询。 |

## 选择规则

综合任务复杂度、风险、质量要求、时延、成本、数据限制和可验证性，选择满足约束的最低充分类别。**不是所有任务使用最高能力模型。**

模型类别建议不代表自动选择、调用、切换、成本批准或结果正确。质量无法验证、数据边界不清、预算不明或模型不可用时，输出 `ESCALATE_FOR_REVIEW` 或 `INSUFFICIENT_EVIDENCE`。
