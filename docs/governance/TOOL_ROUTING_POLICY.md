# Tool Routing Policy

## 原则

工具建议必须具有明确任务价值、必要性、最小权限和可追溯性。Execution Router 只输出建议，不调用工具；真实调用仍由适用 Capability、权限、用户授权和项目 Gate 决定。

| 工具类别 | 可建议的明确价值 | 不应调用的情形 |
|---|---|---|
| 浏览器 / Web | 需要验证时效性外部事实、用户明确要求浏览或需读取指定页面 | 已有本地证据足够，或仅为流程完整。 |
| Git | 需要检查版本状态、历史、差异、提交或合并证据 | 与版本无关的普通咨询，或没有变更 / 授权需求。 |
| 代码执行 | 需要构建、测试、静态验证或复现可核验行为 | 只有概念讨论、未授权写入或无可验证目标。 |
| 文件扫描 | 需要定位受影响文件、依赖、配置或文档关系 | 无差别枚举全仓，或目标文件已明确且上下文足够。 |
| MCP / 外部工具 | 已通过 Capability Admission、权限和安全审查，且提供本地替代无法满足的价值 | 来源、License、权限、数据处理或副作用不明。 |

## 决策合同

每项 Tool Recommendation 记录：任务目标、预期产出、替代方案、最小输入范围、权限 / 数据边界、副作用、回滚或停止条件、Evidence 与 Confidence。无明确价值时输出 `NO_TOOL_REQUIRED`。

## 禁止事项

禁止为了流程完整而调用工具；禁止通过工具调用跳过安全、Gate、用户授权或审查；禁止将工具可用性误作调用授权。
