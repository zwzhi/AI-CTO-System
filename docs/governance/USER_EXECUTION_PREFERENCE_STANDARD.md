# User Execution Preference Standard

## 目的

用户长期偏好可降低重复确认和执行摩擦，但只能影响可选的执行建议，不能改变系统约束或替代当前授权。

## 可记录的偏好

| 偏好类型 | 示例 | 使用前提 |
|---|---|---|
| Git 策略 | 偏好隔离 worktree、提交粒度、已授权时的本地合并方式 | 当前任务已授权、工作区干净、无冲突且用户未给出相反指令。 |
| Review 习惯 | 偏好何时展示设计、计划、差异或合并选择 | 不降低必要审查或安全确认。 |
| 默认模型 | 对低风险任务的类别偏好 | 仍受成本、质量、数据、能力和风险限制。 |
| 默认流程 | 对低风险文档同步的轻量路径偏好 | 任务确属低风险且未触发 Gate / ADR / 安全边界。 |

## 应用规则

1. 偏好必须明确、可撤销、可追溯、当前适用；不从一次选择推断永久规则。
2. Execution Plan 标注 `APPLIED`、`NOT_APPLIED`、`CONFLICTED` 或 `UNKNOWN`，并记录理由。
3. 用户当前指令优先于历史偏好。
4. 用户偏好不能覆盖**安全规则、项目 Gate、ADR、权限、数据政策、License、不可逆操作保护**。
5. 缺少明确偏好、工作区不干净、分支冲突、范围变化或风险升级时，保留人工确认。

## 边界

本标准不修改当前 Git 策略，不自动提交、合并、发布、调用工具或切换模型；它只规定未来 Router 如何形成建议。
